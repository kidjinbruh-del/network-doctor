# Оборудование — Network Doctor 3.0

## Что поддерживается

Один SNMP-коллектор читает стандартные таблицы разных производителей. Идентификация
по sysObjectID использует [IANA Private Enterprise Numbers](https://www.iana.org/assignments/enterprise-numbers/):
MikroTik 14988, D-Link 171, Cisco 9, HPE 11, Aruba 14823, Huawei 2011,
Juniper 2636, Ubiquiti 41112, TP-Link 11863, NETGEAR 4526, Zyxel 890,
Fortinet 12356, Extreme Networks 1916. Неизвестный PEN сохраняется; бренд не угадывается
по открытому порту или имени устройства.

Это не список сертифицированных моделей. Устройство должно предоставлять выбранные
объекты SNMP и разрешать их чтение. Частные MIB и форматы фирменных контроллеров не
подменяются универсальными значениями. Камеры, серверы, UPS, точки доступа и
коммутаторы со стандартными MIB можно опрашивать тем же способом; неуправляемый
коммутатор без IP/агента не может выдать статистику портов.

| Раздел | Данные | Ограничение |
|---|---|---|
| SNMPv2-MIB | имя, описание, PEN, uptime, местоположение | общие данные агента |
| IF-MIB / ifXTable | ifIndex, link/admin, MAC, ёмкость, счётчики и скорости | до 512 нормализованных портов |
| IP-MIB | IPv4 ARP | кэш, не подтверждение текущего online |
| BRIDGE-MIB | FDB, bridgePort → ifIndex | не гарантирует прямой кабель |
| LLDP-MIB | имя и удалённый порт соседа | local LLDP port number не приравнивается к ifIndex |
| Q-BRIDGE-MIB | статические VLAN, egress/untagged bridgePort | не полный список динамических VLAN |
| ICMP | ответы, задержка, потери | без идентификации и метрик портов |

PoE, датчики, CPU по частным MIB, Wi-Fi регистрации фирменных контроллеров,
резервные копии конфигураций устройств и изменения их настроек в универсальный
коллектор не входят. Старые инструменты RouterOS Wi-Fi сохранены отдельно.

## Подключение через GUI

1. Добавьте ID, название, IP/DNS, площадку и ответственного.
2. По умолчанию выбран SNMPv3 **authPriv**: SHA-256 + AES-128. SHA-1 можно выбрать
   для совместимости. MD5, DES и SNMPv3 без шифрования не используются.
3. Укажите SNMPv3 пользователя, auth password и privacy password (8–255 символов).
   В SNMPv2c поле auth используется как community; v2c передаёт его без шифрования.
4. Выберите таблицы: interfaces/extended_interfaces по умолчанию, остальные по
   необходимости. Для сопоставления FDB/VLAN с интерфейсами нужен bridge_ports.
5. Укажите ifIndex портов, которые действительно должны работать, если нужны
   link-down инциденты. Неподключённые прочие порты не считаются аварией.
6. Сохраните профиль и выполните ручной опрос. Мониторинг запускается отдельной
   кнопкой, интервал 15–3600 секунд. Запуск приложения не включает опрос автоматически.

Секреты полей используются только для ручного опроса выбранного устройства.
Фоновый/общий опрос использует окружение или системный keyring. Опция «Сохранить
секреты в keyring» должна быть выбрана явно; при недоступности keyring программа
не сохраняет пароли в открытом SQLite/JSON. В профиле хранятся только имена env:
`ND_SNMP_COMMUNITY`, `ND_SNMP_AUTH`, `ND_SNMP_PRIVACY` (можно задать другие).
Назначьте на оборудовании отдельный read-only профиль и management ACL. Программа
выполняет GET/GETNEXT/GETBULK, методов SET и команд изменения конфигурации в ней нет.

## История, скорости и инциденты

Данные лежат в отдельном `equipment.sqlite` в пользовательском каталоге программы.
`NETWORK_DOCTOR_DATA_DIR` позволяет явно выбрать другой каталог. Для Linux также
учитывается XDG_DATA_HOME. Старый history.sqlite и прежние профили не переносятся
и не перезаписываются.

До 64 профилей, 4 одновременных опроса, 100 последних образцов на устройство,
500 последних инцидентов в списке. На таблицу — 16 384 ячейки, общий полезный объём
ответов ограничен 4 MiB, общий срок одного SNMP-опроса — 5–60 секунд (25 по умолчанию).
Отсутствующая/закрытая MIB отмечается `not_exposed`/`unavailable`; обрезанные ответы —
`truncated`. Недоступность всего опроса записывается ошибкой, не пустым успешным снимком.

Скорость считается по двум сопоставимым снимкам. Перезапуск, изменение ifIndex/name,
сброс, ifCounterDiscontinuityTime, изменение адреса/протокола и неоднозначные
переполнения не превращаются в фиктивные всплески. На быстрых портах с Counter32
может требоваться короткий интервал; Counter64 предпочтительнее. Загрузка full-duplex
берётся по максимуму RX/TX, а не их сумме. Нет данных — значит «—», а не ноль.

Два отказа подряд открывают один инцидент. Новый ответ закрывает инцидент
доступности. Портовые ошибки — по приросту счётчиков, не по старому абсолютному числу.
Закрытие портового инцидента требует нового подтверждающего показателя; пропавшая
таблица не считается восстановлением. Доступны подтверждение, закрытие и журнал
событий. Пользовательское закрытие не отключает правило: новый отказ может открыть
инцидент снова.

## CLI без GUI

```json
{
  "id": "office-switch",
  "name": "Коммутатор офиса",
  "host": "192.0.2.10",
  "protocol": "snmpv3",
  "username": "monitor",
  "site": "Офис",
  "tables": ["interfaces", "extended_interfaces", "lldp", "bridge_ports", "vlans"],
  "expected_ports": [1]
}
```

Сохраните как `profile.json` (192.0.2.10 — адрес документации; замените своим).
Секреты задайте в окружении процесса, а не в файле:

```bash
python -m network_doctor add profile.json
python -m network_doctor poll --device office-switch
python -m network_doctor status
python -m network_doctor history --device office-switch
python -m network_doctor export equipment.html
```

Для отдельного хранилища: `python -m network_doctor --data-dir /path/to/state status`.
Файл профиля не принимает `password` и другие неизвестные поля. CLI poll возвращает
код 2 при отказе хотя бы одного устройства. Автообнаружение credentials, перебор
community и сканирование всей сети не выполняются.

## Prometheus / Grafana

Задайте `ND_METRICS_TOKEN` (минимум 16 символов, случайный токен; не передавайте в URL),
затем запустите единственный фоновый коллектор:

```bash
python -m network_doctor monitor --interval 60 --metrics-port 8776
```

Сервер слушает только 127.0.0.1. `/metrics` требует `Authorization: Bearer ...`,
`/healthz` показывает только состояние процесса. Scrape читает SQLite-кэш, не
создаёт запросов к оборудованию. Старые/неудачные опросы дают nd_equipment_up=0;
портовые серии для них не выдаются как свежие. Метрики полосы экспортируются только
из Counter64, чтобы скрытые переполнения Counter32 не портили графики.

`deploy/prometheus/scrape.yml` — фрагмент для Prometheus **на том же хосте**.
Токен поместите в указанный закрытый файл; конфиг содержит только путь к нему.
Docker localhost — другой сетевой namespace, поэтому этот пример нельзя без
изменений переносить в контейнер. Внешний доступ требует отдельного HTTPS proxy,
ACL и осознанной настройки владельцем. CLI не открывает 0.0.0.0 и firewall сам.

Импортируйте `deploy/grafana/network-doctor.json` в свою Grafana и выберите datasource.
Пример alert rules: `deploy/prometheus/alerts.yml`. Доставка требует настроенного
Alertmanager и каналов; наличие файла правил само по себе уведомлений не отправляет.
Дашборд — шаблон; импорт в живую Grafana на этом этапе не испытывался.

Не запускайте GUI-мониторинг и CLI-коллектор для одного профиля одновременно.
Это два отдельных процесса с общей SQLite-историей, а не распределённый scheduler.

## Изменения старой диагностики

- Автоматический spectral-scan отключён: активный радио-тест может мешать работе.
  Низкоуровневый клиент допускает его только с явным `active_tests=True`.
- Новые GUI-профили RouterOS выбирают API-SSL с проверкой сертификата; можно указать
  CA PEM. Прежние явно сохранённые настройки не заменяются принудительно.
- Privacy/randomized MAC не считается доказательством виртуализации. Такие клиенты
  больше не исключаются только из-за locally administered bit.
- Без измерений Health Score неизвестен; закрытый management порт или ровный NAT
  сами по себе не доказывают причину отсутствия интернета.

## Проверка

Тесты запускают loopback SNMP-агент с синтетическими данными и настоящим UDP,
проверяют v2c/v3 authPriv, неверные credentials, счётчики/VLAN/LLDP, отмену,
дедупликацию инцидентов и безопасный экспорт. Linux GUI-тест под Xvfb выполняет
опрос через настоящий CTk-интерфейс и сохраняет скриншот в artifact CI.
Физические устройства, реальные VLAN/LLDP каждой модели, keyring конкретной
организации и фоновая эксплуатация на крупном парке требуют отдельных испытаний.

Источники стандартов:
[IF-MIB](https://www.rfc-editor.org/rfc/rfc2863.html),
[Q-BRIDGE-MIB](https://www.rfc-editor.org/rfc/rfc4363.html),
[PySNMP](https://docs.lextudio.com/pysnmp/v7.1/docs/pysnmp-hlapi-tutorial).
